## 1. 每次执行前先记住的结论

1. **这轮改造不是给旧页面套一层皮肤，而是在建立一套“算法图谱”视觉语言。**
2. **A 类可复用的是方法和工程骨架，不是背包造型、金色材质或所有尺寸。**
3. 每一类至少要有三层相互呼应、但职责不同的视觉：
   - 分类页首屏：完整、可识别、有记忆点的“主雕塑”。
   - 分类页课程路径：同一视觉母题的线框或结构稿，服务于列表导航。
   - 课程内容页：每课唯一、能说明状态或转移的“语义图版”。
4. 任何图形都应回答一个算法问题。仅仅“好看”的网格、圆环、箭头和粒子不能成为主体。
5. 内容页首先是阅读页面，其次才是展示页面。正文行宽、标题位置、交互操作和移动端阅读不能为了大图牺牲。
6. 深浅主题必须保持同一几何、同一信息、同一交互，仅改变材质和颜色变量，切换时不能像换了一张图。
7. 视觉验收必须进入真实浏览器，覆盖深浅主题、桌面和移动端，并检查控制台、溢出和真实交互。`build` 通过不是视觉验收。
8. 在继续做 B–G 前，先通过家族艺术注册表消除艺术组件中的 `part.id === 'a'` 分支扩散，并保持当前路由按需加载。

## 2. 不可回退的产品基线

这些是当前产品决定，不应在后续视觉改造中被意外还原：

- 网站名称为“DP大师”，英文副名称为“DP Master”。
- 不再使用“动态规划交互式教程”作为品牌介绍。
- 项目没有账号、数据库和学习进度系统。
- 左侧导航不显示课程完成后的绿色对勾。
- 不重新引入本地学习进度、`dp-master-progress:v1`、`lesson_started` 或 `lesson_completed` 等状态逻辑。
- 普通访问统计仍保留；EdgeOne 构建的 `betaoi.cn` 页面应注入一次 Cloudflare Web Analytics，Cloudflare 自身承载的页面不能重复注入。
- 分类首屏主按钮应沿用全站统一的尺寸、圆角和交互，不为某一类另造一套按钮规格。
- 分类页的课程数文字应与按钮在视觉中心线上对齐，而不是贴着按钮底部。
- 共享的侧栏、主题切换、反馈入口、首页七大主题动效不属于本轮家族改造主体；若未明确需要，不要顺手重写。
- 反馈表单现行契约不得回退：标题“问题反馈”，分类为“内容错漏 / 显示异常 / 其他建议”，设备诊断自动提交，当前页面信息自动携带而不要求用户填写。

## 3. A 类改造到底解决了什么

### 3.1 改造前的主要问题

- 分类主页主要是课程子类列表与小游戏入口，缺乏清晰的家族身份。
- 课程内容页像课件、PPT 或 Markdown 信息页：标题、图片、正文、算法互动彼此割裂。
- 大量卡片、统一圆角和规则网格带来明显的 SaaS 模板感。
- 所有课程共用抽象装饰，图形与具体状态转移没有关系。
- 正文容器偏窄，桌面端右侧留下大块无效空间。
- 大图和标题依赖硬编码位置，改一个视口后容易在另一个视口错位。
- 深浅主题若使用不同背景图，会让切换产生内容变化感。

### 3.2 A 类形成的设计命题

A 类最终不是“做了一只背包”，而是建立了以下关系：

| 层级 | 视觉职责 | A 类做法 | 后续六类应继承的原则 |
|---|---|---|---|
| 分类首屏 | 建立家族第一印象 | 低多边形实体背包 + 构造线 | 一眼能认出家族，但不代替文字 |
| 课程路径 | 解释家族内部结构 | 9 个真实课程链接组成“物品件数 / 约束结构 / 目标与边界”三条容量谱系带 | 导航本身必须成为图谱，不能退回“列表旁附一张说明图” |
| 课程页头 | 概括本课状态或转移 | 9 个课程各自独立图版 | 每课唯一且有算法语义 |
| 正文插图 | 支持推导 | 状态表、转移路径、边界关系 | 只在有信息价值时使用 |
| 互动实验 | 验证理解 | 使用真实求解器与真实状态 | 不能用装饰性假数据冒充算法 |

### 3.3 “同一母题，三种表达”

这条是整个后续改造的核心：

- **主雕塑**表达“这是什么家族”。
- **结构稿**表达“这个家族由哪些课程构成”。
- **课程图版**表达“这一课的状态、转移、方向或约束是什么”。

三者应共享形态语言，但不能把同一个 SVG 原封不动放三遍。否则既显重复，也没有信息层级。

### 4.1 A 类图形组件的关键实现

`PolygonBackpack.tsx` 当前包含：

- 实体与线框共用的一套确定性几何。
- 38 个多边形面组成的背包轮廓。
- 与背包轮廓分层的构造圆、轴线和辅助线。
- 9 个按 slug 映射的独立课程图版：
  - `01`：物品进入 `0 / 1` 决策分叉，合并到“保留较优”，并标出容量倒序。
  - `complete`：容量正向更新轨道。
  - `multiple`：二进制拆分包裹。
  - `group`：组内互斥选择。
  - `mixed`：01 / 完全 / 多重三类分派。
  - `cost2d`：物品的费用 `a / b` 与价值 `v`，以及 `(x-a,y-b) → (x,y)` 的二维状态转移。
  - `dep`：主件、附件和合法组合。
  - `variant`：最值、计数、可达性等目标变形。
  - `fractional`：单位价值排序和可分割容器。
- 使用 `useId` 避免部分滤镜 ID 冲突。
- 只在允许动画时启用动效，尊重 `prefers-reduced-motion`。

### 4.2 A 类页面布局的最终校准点

- 分类首屏采用左右非对称构图，而不是等宽卡片。
- 主 CTA 最终回归通用按钮规格，不保留 A 类私有尺寸。
- “9 门课程”与 CTA 以垂直中心对齐。
- 课程路径采用三条开放谱系带，课程链接本身同时承担导航与图谱节点职责；艺术层只贯穿链接，不再出现“左列表 + 右插图”。
- 课程页桌面标题实际文字左边缘与正文左边缘对齐；不能只看标题容器坐标。
- 正文采用基于 `ch`、百分比和最大值的自适应行宽，桌面不再留下过大的右侧空白。
- 移动端标题左边距归零到内容栅格，课程图版缩放且不产生横向滚动。
- Demo 正文具备桌面 24–32px、移动端至少 12px 的安全内边距。
- DPViz 显式声明 `table / panel / legend / playback` 区域，并根据 Demo 容器宽度而非只根据 viewport 堆叠。
- 首页不再预载无关页面和家族艺术；旧文档遇到失效 hash 时，每个构建与路径最多自动恢复刷新一次。

## 5. B–G 共用的工程抽象

### 5.1 不要继续添加家族特判

当前 A 类是试验田，存在如下代码形态：

```tsx
part.id === 'a' ? <PolygonBackpack /> : <PartGlyph />
```

若按这个方式继续六类，很快会形成：

- `PartPage.tsx` 内 7 分支；
- `TypePage.tsx` 内 37 个 slug 分支；
- CSS 中 7 份高度相似的布局；
- 首屏一次性导入所有家族的重 SVG；
- 修复一个公共问题要改 7 次。

家族艺术契约采用以下职责：

```ts
type FamilyArtModule = {
  HeroArt: React.ComponentType<FamilyArtProps>
  JourneyArt: React.ComponentType<FamilyArtProps>
  LessonPlate: React.ComponentType<LessonPlateProps>
}

type FamilyArtProps = {
  mode?: 'solid' | 'wireframe'
  className?: string
}

type LessonPlateProps = {
  slug: string
  title: string
  className?: string
}
```

注册表只负责把 `partId` 映射到懒加载艺术模块及其构建期 source：

```ts
const familyArtLoaders = {
  a: () => import('./families/backpack'),
  b: () => import('./families/linear'),
  // ...
}
```

注意：

- `catalog.ts` 仍然是课程标题、slug、文案、顺序和内容模块的唯一来源。
- 艺术注册表不能复制一份课程标题和顺序，否则后续会出现双数据源。
- 只加载当前路由所属家族的艺术模块，不要让访问 B 类时下载 A–G 全部 SVG。
- 当前路由的艺术模块必须与页面/课程正文一起在客户端水合前准备，并加入静态 HTML 的 CSS 与 modulepreload 清单。
- 组件渲染必须确定性，不能在 render 中使用 `Math.random()` 生成点位或 ID。

### 5.2 建议的目录结构

可以在开始 B 类时完成一次小规模整理：

```text
site/src/components/art/
├─ shared/
│  ├─ ScientificPlate.tsx
│  ├─ svgIds.ts
│  ├─ primitives.tsx
│  └─ family-art.css
├─ families/
│  ├─ backpack/
│  │  ├─ BackpackHero.tsx
│  │  ├─ BackpackLessonPlate.tsx
│  │  └─ backpack.css
│  ├─ linear/
│  ├─ interval/
│  ├─ matrix/
│  ├─ reroot/
│  ├─ tree/
│  └─ bitmask/
└─ familyArtRegistry.ts
```

不必为了目录漂亮而一次性重写 A 类。最稳妥的方式是：

1. 先写契约和注册表。
2. 把 A 类接入新契约，确保截图和测试不变。
3. 再用 B 类验证抽象是否真的可用。
4. B 类完成后再决定是否进一步拆分公共原语。

### 5.3 公共 SVG 原语可以共享，构图不能共享

适合共享的原语：

- 唯一 ID 生成；
- 箭头 marker；
- 轴线、刻度、节点、标签、括号、路径；
- 状态单元格和高亮；
- 噪点、纸张、金属或发光材质变量；
- `<title>`、`aria-labelledby` 等可访问性包装；
- reduced-motion 处理。

不适合强行共享的内容：

- 背包轮廓、树冠轮廓、超立方体等主几何；
- 每课的状态排布；
- 为了兼容所有家族而产生几十个布尔参数的“万能图版”；
- 所有家族统一为金色或统一为网格。

### 5.4 CSS 分层标准

建议把样式分成三层：

1. **全站阅读层**：页面宽度、正文 measure、标题与正文对齐、目录、移动端断点。
2. **图谱布局层**：首屏左右结构、课程路径、主雕塑与线框图的位置、通用 CTA。
3. **家族艺术层**：该家族的色相、线型、形态、局部尺寸与课程图版构图。

原则：

- 家族 CSS 不应复制完整的 `.typepage` 或 `.partpage` 布局。
- 通用按钮、正文宽度、移动端内边距只在公共层定义一次。
- 尽量使用 `clamp()`、`min()`、`max()`、`ch`、百分比和容器空间，不使用只对单一截图成立的固定宽度。
- 对大图使用明确的锚点和视觉中心，不靠反复微调 `top: -13px` 之类的补丁堆叠。

### 5.5 通用 Demo Workbench

Demo 样式分为两层：

1. `components/demos/shared/demo-workbench.css`：工具条、步进器、编辑列表、读数、容器查询和跨家族安全布局。
2. 家族专属 CSS：只保留该算法输入结构和专属对照实验。

迁移原则：

- 非背包 Demo 不再导入 `knapsack-demo.css`。
- 首轮只迁移样式所有权，不改 solver、输入契约和 DOM 语义。
- 历史 `.kd__*` / `.fbug__*` 类名可暂留在共享层，随各家族改造渐进重命名，避免一次性重写 32 个 Demo。
- 页面级横向滚动始终视为缺陷；大表只允许在自身滚动容器内滚动。

## 6. 六大家族的视觉方向与课程图版草案

这些不是必须一字不差照做的成品设计，而是概念板探索的“语义边界”。每个图形都要先验证它是否解释了本课，再讨论材质和细节。

### 6.1 B · 线性 DP

**家族母题：沿时间或索引前进的轨道、折线、标尺与序列脊线。**

- 首屏主雕塑：7 个多面体状态沿有厚度的索引脊椎顺序推进，较早状态以 4 条前驱轨带汇入高亮当前状态，脊椎下方的折叠带表达滚动状态。
- 课程路径背景：同源的双轨线框标尺，首行左→右、次行右→左就近折返，课程链接直接落在轨道上。
- 风险：不能把所有课程都画成一条普通折线；LCS、编辑距离实际是双序列或二维状态。

| slug | 课程 | 建议图版语义 |
|---|---|---|
| `path` | 路径型 / 递推入门 | 三角形或阶梯路径，突出“来自前一层” |
| `maxseg` | 最大子段和 | 正负条带与被框选的最优连续区间 |
| `lis` | 最长上升子序列 LIS | 序列点、上升链与 `tails` 层叠牌堆 |
| `lcs` | 最长公共子序列 LCS | 两条字符轨道，匹配点连接成单调链 |
| `edit` | 编辑距离 | 双序列矩阵中的删、插、改三向箭头 |
| `fsm` | 线性状态机 DP | 同一时间刻度上的多个状态轨道与受限切换 |
| `count` | 计数 / 划分型 | 总量被拆成有序层级或生成路径汇流 |

### 6.2 C · 区间 DP

**家族母题：两端点之间的张力、嵌套弧、括号、桥与不断收缩的空间。**

- 首屏主雕塑：多个相互嵌套、跨越端点的弧形桥，形成明显的区间层次。
- 课程路径背景：由大到小的线框区间壳层，列表像位于端点之间。
- 风险：不要把“区间”简单画成一堆圆环；端点、长度、分割点必须可感知。

| slug | 课程 | 建议图版语义 |
|---|---|---|
| `stone` | 石子合并（链形） | 区间 `[l,r]` 与分割点 `k`，左右代价汇合 |
| `ring` | 环形区间 DP | 环被切开并复制首段，明确“断环为链” |
| `palindrome` | 回文 / 括号 | 两端向内收缩，匹配端点形成闭合括号 |
| `tree` | 加分二叉树型 | 区间中枚举根，左右区间长成子树 |
| `merge` | 合并 / 删除类 | 相同块跨过已消除区间重新连接 |

### 6.3 D · 矩阵 DP

**家族母题：晶格、矩阵块、折叠平面与变换。**

- 首屏主雕塑：由多个矩阵平面叠合、旋转或相乘形成的块体。
- 课程路径背景：线框矩阵平面与变换轴。
- 风险：D 只有两课，不能为了填满页面制造大量无意义课程装饰；路径区应更紧凑。

| slug | 课程 | 建议图版语义 |
|---|---|---|
| `grid` | 网格 / 矩阵上的 DP | 网格上的路径、最大正方形和双路径冲突区域 |
| `matpow` | 矩阵快速幂加速 | 状态向量经 `A, A², A⁴` 层层折叠到目标 |

### 6.4 E · 换根 DP

**家族母题：同一棵树围绕不同中心重排，带有放射、轨道和双向信息流。**

- 首屏主雕塑：一棵树的多个中心投影叠合，中心移动后枝条权重发生变化。
- 课程路径背景：树形线框加一条穿过不同根的“巡游轨道”。
- 风险：必须看出“换根”，不能只画一棵普通树；向下与向上两次传递要可区分。

| slug | 课程 | 建议图版语义 |
|---|---|---|
| `basic` | 换根基础模型 | 第一次子树汇总、第二次父侧回传的双扫描 |
| `distsum` | 距离和换根 | 根跨过边后，两侧节点数导致距离和增减 |
| `inout` | 子树内外合并 | 节点内侧状态与父侧外部状态在根处合成 |
| `center` | 中心 / 偏心距 | 最长和次长链、直径端点与中心收敛 |

### 6.5 F · 树形 DP

**家族母题：分叉树冠、树轮、子树容器与自底向上的汇聚。**

- 首屏主雕塑：具备主干、层级和分叉密度的多边形树冠。
- 课程路径背景：线框树冠，课程节点沿主干或树轮分布。
- 风险：E 和 F 不能只是换颜色的树。E 强调根移动与双向流，F 强调子树汇总和状态组合。

| slug | 课程 | 建议图版语义 |
|---|---|---|
| `select` | 选点 / 最大独立集 | 每个节点“选 / 不选”两态与父子冲突 |
| `knapsack` | 树上背包 | 子树状态包逐个合并到父节点容量 |
| `diameter` | 直径 / 重心 DP | 节点处最长、次长向下链合成一条直径 |
| `cover` | 覆盖 / 支配 / 染色 | 三状态节点、覆盖范围与父子合法组合 |
| `count` | 方案数 / 距离统计 | 子树计数层层卷积或按距离壳层汇聚 |

### 6.6 G · 状压 DP

**家族母题：比特点阵、状态星座、超立方体和移动轮廓线。**

- 首屏主雕塑：由明灭比特构成的立体状态晶格或超立方体投影。
- 课程路径背景：稀疏线框状态空间，避免满屏密集小格。
- 风险：这是信息密度和移动端风险最高的一类；不要把二进制字符铺满背景，也不要使用不可读的炫技 3D。

| slug | 课程 | 建议图版语义 |
|---|---|---|
| `board` | 棋盘 / 轮廓状压 | 行状态位掩码、相邻合法性与逐行转移 |
| `tsp` | 集合状压 / TSP | 子集节点形成状态星座，最后一维表示终点 |
| `cover` | 状压 + 覆盖 | 几何对象覆盖目标点后合成为掩码 |
| `subset` | 综合技巧 | `mask` 的子集遍历与状态汇流 |
| `plug` | 插头 DP（选修） | 扫描轮廓线、插头配对和连通性编码 |

## 7. 推荐实施顺序

建议顺序为：

1. **B 线性 DP**：课程数多、语义熟悉，最适合验证艺术注册表和公共图版原语。
2. **C 区间 DP**：验证非线性构图、端点和分割点表达。
3. **D 矩阵 DP**：只有两课，适合作为中途的架构与质量检查点。
4. **E 换根 DP**：先建立树、箭头、双向流和根切换原语。
5. **F 树形 DP**：复用树的基础原语，但必须形成不同于 E 的家族身份。
6. **G 状压 DP**：视觉和移动端信息密度最高，放在公共体系稳定后处理。

不要同时铺开六类。建议每完成一类就达到可独立上线的 Definition of Done，再进入下一类。

每个家族固定经过：

1. 概念板确认；
2. 分类页 + 两个代表性图版确认；
3. 完成余下课程并运行完整验证；
4. 发布确认、独立部署和线上观察。

## 8. 每一家族的标准 workflow

### Phase 0：建立干净基线

- 从项目根目录确认当前分支、远端和工作区。
- 所有 npm 命令在 `site/` 目录执行。
- 先跑与即将修改区域相关的现有测试，确认基线不是红的。
- 如果使用分支或 worktree，记录准确路径和服务 PID；最终清理前先停止占用该路径的预览服务。

交付物：

- 干净的 `git status`。
- 当前桌面与移动端基线截图。
- 已知问题清单，而不是边改边回忆。

### Phase 1：内容与状态审计

逐课阅读：

- `catalog.ts` 中的标题、blurb、slug；
- 对应 `site/src/content/{part}/` 课程正文；
- 当前 Demo、Solver 和小游戏；
- 状态定义、转移方向、初始化、边界与常见错误。

为每课写一句“图版必须说明什么”。如果这句话写不出来，就先不要画图。

交付物：

- 家族母题一句话。
- 每课图版语义一句话。
- 需要真实状态数据支持的图版列表。

### Phase 2：概念板与保真清单

在 `docs/concepts/{code}-{family}/` 下建立：

- 深色概念板；
- 浅色概念板或同几何材质方案；
- 分类首屏；
- 课程路径；
- 至少 2–3 个代表性课程图版；
- `README.md`，记录必须保留、允许变化和禁止出现的元素。

概念图只能是视觉参考，不能直接作为网页背景图。实际页面应由 SVG、CSS 和真实 DOM 重建，确保响应式、主题和可访问性可控。

交付物：

- 同一几何的深浅主题方案。
- 明确的保真清单。
- 移动端简化策略。

### Phase 3：先接通工程骨架

- 家族艺术模块接入注册表。
- 首屏和路径使用同源几何。
- 课程页能按 slug 选择唯一图版。
- 为 SVG 滤镜、渐变、marker 和 clipPath 生成实例唯一 ID。
- 保持课程正文和家族游戏懒加载。

此阶段不追求精修材质，先证明结构成立。

交付物：

- 分类页可导航。
- 所有课程图版都有唯一 `data-*` 或可访问名称。
- 没有 A/B/C 连环条件分支扩散。

### Phase 4：完成分类主页

逐项校准：

- 主标题、摘要、CTA、课程数的层级与对齐。
- 首屏主雕塑的视觉中心、留白和正文关系。
- 课程路径中列表与线框背景的中心关系。
- 课程只有 2–5 门时，不强行使用与 9 门课程相同的固定高度。
- 家族小游戏仍然是页面结尾的“实验场”，不能抢走课程路径主体。

判断艺术位置时使用可测量的中心：

```text
列表视觉中心 = (第一课内容顶部 + 最后一课内容底部) / 2
图形视觉中心 = SVG 实际可见轮廓包围盒中心
```

不要只比较 SVG 元素盒子的中心，因为透明 viewBox 和装饰线会欺骗布局。

### Phase 5：完成课程页头与课程图版

- 每课一个唯一构图，不能只替换标题文字。
- 图版首先展示本课的核心状态或转移。
- 标题区实际 `h1` 左边缘与正文左边缘对齐。
- 长标题单独验证，尤其含英文缩写、斜杠和括号的课程。
- 图版的文字标签不能贴边、重叠或在缩放后不可读。
- 同心圆、轴线等共享装饰应服从标题，不压住标题或正文。

### Phase 6：正文与互动的编辑化改造

不要把正文全部做成卡片。建议用以下层级：

- 普通段落保持连续阅读。
- 关键定义用克制的侧线、编号或小标题。
- 状态表和对比表保留结构，不伪装成装饰插画。
- Example、Exercise、Demo 使用已有公共组件与内容约定。
- 真实算法过程由已有 solver 驱动；需要新增数据时优先扩展 solver，不在视图层硬编码答案。
- 交互必须保留播放、暂停或单步、重置、速度和可编辑输入等已有能力。

正文行宽标准：

- 以可读字符数和可用空间共同决定。
- 桌面端不应因固定 `max-width` 在右侧留下大块空白。
- 小屏应使用完整内容宽度并保留安全内边距。
- 代码、表格和 Demo 可比正文宽，但不能导致页面横向滚动。

### Phase 7：主题、响应式与动效

主题：

- 几何、标签、顺序、状态必须完全一致。
- 只切换 CSS token、材质、阴影、线条明度和纹理强度。
- 不用两张内容不同的背景图制造深浅主题。

响应式：

- 至少验证 1600×1000、1440×900、约 1024、约 820 和 390×844。
- 820 附近重点检查桌面目录切换为移动目录时的布局。
- 移动端优先保标题、核心几何、关键标签和操作按钮；辅助构造线可以降低透明度或隐藏。
- 所有页面必须满足 `scrollWidth === clientWidth`。

动效：

- 路由进入和图形动效都要克制，不能大幅飞入。
- 拖动、吸附和自动到位不能制造虚影、错位或二次抖动。
- `prefers-reduced-motion: reduce` 下应去除非必要动画。
- 动画不能改变算法状态的最终可读性。

### Phase 8：浏览器 QA 与自动化

自动化命令从 `site/` 执行：

```bash
npm run lint
npm run test:unit
npm test
npm run build
npm run check:analytics
npm run check:assets
npm run test:browser
npm run verify
```

日常开发可先跑聚焦测试，准备交付时再跑完整 `npm run verify`。

浏览器人工 / Playwright 验收矩阵：

| 维度 | 最低覆盖 |
|---|---|
| 家族 | 当前分类页 + 所有课程页轻量巡检 |
| 主题 | light、dark |
| 桌面 | 1600×1000、1440×900 |
| 断点 | 1024 左右、820 左右 |
| 移动 | 390×844 |
| 交互 | CTA、课程跳转、目录、Demo 播放/重置/输入、主题切换 |
| 稳定性 | console error/warn、框架错误层、404、横向溢出 |
| 可访问性 | 键盘焦点、SVG title/label、对比度、reduced motion |

每一家族至少留存：

- 分类页深色桌面截图；
- 分类页浅色桌面截图；
- 课程路径完整截图；
- 代表性课程页桌面截图；
- 长标题课程截图；
- 移动端分类页和课程页截图；
- 真实 Demo 操作后的截图或断言。

### Phase 9：文档、提交与清理

- 更新该家族的概念说明和实现差异记录。
- 检查是否误改生成文件；`problems.ts` 只能通过生成器更新。
- `git diff --check`。
- 核查实际 diff，确认没有混入其他家族的无关改动。
- 提交信息按“架构 / 家族实现 / 精修 / 测试”保持可追溯。
- 合并后停止预览服务，再移除 worktree 和临时分支。

## 9. 已踩坑、原因与预防方式

### 9.1 SVG 噪点出现矩形高亮

**现象**：背包内部纹理之外出现一块明显的矩形亮区。  
**原因**：`feTurbulence` 或 blend 作用于整个 filter 区域，未裁到源图形 alpha。  
**正确做法**：先把 grain 与 `SourceAlpha` 用 `feComposite operator="in"` 相交，再进行 blend。  
**预防**：任何纹理滤镜都在深浅主题和纯色背景上单独检查 filter 边界。

### 9.2 列表背景图“太靠上”

**现象**：CSS 看起来已经居中，但背包仍压在前几课上方。  
**原因**：元素盒子中心不等于可见轮廓中心；课程列表自身也可能有顶部说明区和底部留白。  
**正确做法**：测量第一课到最后一课的实际内容中心，与 SVG 可见轮廓中心比较。A 类最终二者误差约 1px。  
**预防**：每类都把“列表中心差”作为可测 QA 项。

### 9.3 家族 CTA 与全站不一致

**现象**：A 类按钮曾是直角、尺寸不同，视觉上像另一个产品。  
**原因**：家族专属样式覆盖了全站 CTA。  
**正确做法**：按钮命中公共规格，家族只改变必要的色彩或局部装饰。  
**预防**：浏览器测量按钮宽高、圆角与基准家族对比。

### 9.4 课程数看似对齐但视觉不齐

**现象**：“9 门课程”靠近按钮底边。  
**原因**：flex 使用了 `align-items: flex-end` 或文字行高造成假中心。  
**正确做法**：用中心线比较，并检查文字实际 line box。  
**预防**：桌面、移动端都截图检查，不能只看 CSS 声明。

### 9.5 标题区移动了，标题文字却仍偏左

**现象**：调整 `typehead__copy` 后仍觉得 `h1` 不对齐。  
**原因**：比较的是容器 x，而不是实际文字 x；内部 padding、grid gap 和装饰列还会叠加。  
**正确做法**：在浏览器读取 `h1.getBoundingClientRect().x` 和正文首段 x。  
**预防**：把“标题文字与正文左边缘差值”纳入桌面断言；移动端应重置额外偏移。

### 9.6 正文写死宽度导致右侧浪费

**现象**：大屏右侧仍有很大空白，正文像窄 PPT。  
**原因**：固定 `max-width` 只适配单一视口。  
**正确做法**：使用 `min(100%, clamp(...ch, ...%, ...ch))` 一类自适应 measure。  
**预防**：同时测 1440 与 1600；代码块和 Demo 还需测横向溢出。

### 9.7 长标题破坏构图

**高风险课程**：

- “最长公共子序列 LCS”
- “路径型 / 递推入门”
- “辨析：分数背包=贪心”
- “网格 / 矩阵上的 DP”
- “覆盖 / 支配 / 染色”
- “插头 DP（选修）”

**处理**：用 `clamp()`、受控换行和家族级少量标题修正，不为每个标题写绝对坐标。

### 9.8 移动端大图造成横向滚动

**原因**：固定 SVG 宽度、绝对定位、transform 后包围盒越界，或标签没有缩放。  
**处理**：

- SVG `width: 100%` 配合合理 `viewBox`；
- 移动端把艺术层纳入正常栅格；
- 必要时降低辅助线而不是裁掉核心图形；
- 最终用 DOM 断言检查页面实际 `scrollWidth`。

### 9.9 SVG ID 冲突

**风险**：多个图版同时出现时，静态 `marker id="arrow"`、gradient 或 clipPath 会互相引用。当前部分 marker 仍值得统一检查。  
**处理**：所有 defs ID 通过 `useId()` 派生，`url(#id)` 使用同一实例值。  
**预防**：在同一测试页同时渲染两张图版，确认箭头、滤镜和渐变没有串线。

### 9.10 装饰网格冒充算法信息

**现象**：每课都铺网格，看起来“科技”，但与算法无关。  
**标准**：网格只在状态本身是二维或棋盘时使用，如二维费用、编辑距离、矩阵、棋盘状压。  
**替代**：线性用轨道，区间用端点与弧，树类用枝干和信息流，状压用稀疏状态空间。

### 9.11 图版使用假数值

**风险**：视觉演示与正文算法或 Demo 结果不一致。  
**处理**：状态表和播放路径由真实 solver 或稳定 fixture 生成；静态示意若不是计算结果，要明确它只是结构图。  
**预防**：测试一个已知输入，断言关键单元格与 solver 输出一致。

### 9.12 一次性加载所有家族艺术

**原因**：顶层静态 import 一个包含 37 个图版的大文件。  
**处理**：按当前家族动态导入，再在模块内部按 slug 选择轻量组件。  
**预防**：检查构建 chunk；进入 B 类不应拉取 E/F/G 的艺术模块。

### 9.13 render 中随机生成艺术点位

**风险**：SSR、hydration、截图测试和主题切换时图形不稳定。  
**处理**：点位固定，或由 slug/固定 seed 在模块初始化阶段确定；不要每次 render 随机。  
**预防**：同一路由刷新两次做像素或 DOM 属性比较。

### 9.14 动效幅度过大或吸附抖动

**现象**：拖动中虚影、错位，松手后强制到位产生二次抖动。  
**处理**：

- 拖动时只更新单一 transform 源；
- 不让 CSS transition 与手势动画同时争夺 transform；
- 松手只执行一次基于速度和阈值的 snap；
- 动画开始前取消旧动画；
- 动画完成后统一索引和位置；
- reduced-motion 下直接落到最终状态。

虽然该问题主要出现在首页七大主题轮播，但未来家族图谱若加入拖动或视差，同样适用。

### 9.15 Playwright 在 Windows 上测试通过后不退出

**现象**：断言已经显示通过，命令仍挂着。  
**原因**：托管 `webServer` 的子进程未正确回收，不代表测试失败。  
**处理**：

- 先确认 worker 和断言已经结束；
- 使用手动启动的预览服务配合不托管 `webServer` 的配置；
- 只终止本次服务的准确 PID，不做宽泛进程清理。

### 9.16 移动端 locator 歧义

**现象**：桌面目录和移动目录同时存在 DOM，Playwright 文本定位命中两个元素。  
**处理**：按可见容器、role、`data-*` 或明确作用域定位，不使用无作用域的裸文本。

### 9.17 预览服务锁住 worktree

**现象**：Windows 删除 worktree 失败。  
**原因**：Node/Vite 进程当前目录或打开文件仍在 worktree。  
**处理**：先核对并停止准确 PID，再执行 worktree 清理。

### 9.18 把 A 类 CSS 整份复制六遍

**后果**：同一个标题、正文、按钮或断点问题需要修七次。  
**处理**：先抽公共 atlas/readability 层，再写家族构图差异。  
**判断标准**：如果一个 selector 不包含家族语义，它大概率不该在家族 CSS 中。

### 9.19 带图标的提示块把强调文字或链接挤成竖排

**现象**：提示块第一行正常，后续的 `<strong>`、`<a>` 或数学节点却落进只有二十余像素宽的图标列，汉字逐字竖排。  
**原因**：容器使用两列 CSS Grid，但 JSX 中的裸文本、强调、链接和数学节点都是直接子节点；Grid 会把它们分别当作独立网格项自动排布，而不是一段连续的行内内容。只给容器增加宽度无法解决。  
**处理**：

- 提示内容保持正常 block/inline formatting context；
- 图标改为相对容器绝对定位，并用左侧 padding 留位；
- 或显式增加一个统一的 `pointer-cue__copy` 包装层，所有行内节点只存在于该层；
- 回归时检查提示块的直接子节点，不能出现“宽度很窄但高度异常”的文字节点。

**本次实测**：A 类九课桌面端提示块由最高约 `886px` 收敛为常规 `70–116px`，移动端也保持正常换行。

### 9.20 DP 表格和解说面板依赖隐式 Grid 自动排布

**现象**：表格只占左半边，右半边留出大片空白；公式、解说和播放控制被推到表格下方，演示卡高度异常。  
**原因**：容器声明了两列，但没有声明 `grid-template-areas`。当图例需要跨列时，浏览器会按 DOM 顺序隐式放置后续节点，解说面板不一定进入预期的右列。  
**处理**：

- 桌面端明确使用 `table / panel / legend / playback` 网格区域；
- 移动端明确改为 `table → legend → panel → playback` 单列顺序；
- 表格过宽时只允许表格自身横向滚动，禁止页面级横向溢出；
- 桌面回归应断言表格与解说面板顶部对齐，移动端应断言解说面板位于表格下方。

**本次实测**：A 类九课所有 DP 演示的桌面表格与解说面板顶部已对齐，移动端全部正确堆叠；典型演示高度由约 `510px` 降至约 `370px`，页面无横向溢出。

### 9.21 SVG `<title>` 的相邻文本节点导致生产水合失败

**现象**：开发服务器页面正常，但生产预渲染的 B 课程直达页出现 React 可恢复水合错误；浏览器最终仍能显示图版，因此容易被只看截图的验收漏掉。

**原因**：`<title>{title}状态图</title>` 生成两个相邻文本节点。React 19 静态预渲染对 `<title>` 有特殊处理，服务端结果成为空 SVG 标题，而客户端首次渲染得到完整标题，HTML 不一致。

**正确做法**：把可访问标题合成为单一确定性字符串节点：``<title>{`${title}状态图`}</title>``。

**预防**：代表课程的生产预览测试必须同时断言 SVG `<title>/<desc>`、直达页 console 为 0 和真实水合；不能只在 Vite 开发服务器检查。

## 11. 自动化测试建议

### 11.1 分类页图谱测试

对每个家族验证：

- 存在唯一主雕塑；
- 存在同源线框图；
- 不再出现通用 `PartGlyph`；
- 课程行数与 `catalog.ts` 一致；
- CTA 指向第一课；
- 每一行课程链接可访问；
- light/dark 下 DOM 几何结构一致；
- 桌面和移动端无横向溢出。

### 11.2 课程图版测试

对全部 37 课做轻量结构断言：

- `data-lesson-plate` 等于 slug；
- SVG 有课程相关的 `<title>` 或 accessible name；
- 不出现通用占位图；
- 页面标题和正文存在；
- 前后课程导航来自 `catalog.ts`。
- 带图标提示块没有窄列竖排的行内文字；
- 桌面端 DP 表格与解说面板顶部对齐；
- 移动端 DP 解说面板按顺序堆叠在表格后；
- 表格内部可以独立滚动，但页面本身没有横向溢出。

每个家族再选 1–2 课做深度测试：

- B：LIS、编辑距离；
- C：石子合并、环形区间；
- D：矩阵快速幂；
- E：距离和换根；
- F：树上背包、覆盖；
- G：棋盘状压、插头 DP。

深度测试应操作真实 Demo，并断言状态变化，不只检查按钮存在。

### 11.3 视觉回归阈值

不建议一开始给整页设置过严像素阈值。先稳定：

- 主图包围盒；
- 标题和正文 x 差值；
- 课程列表与背景图中心差；
- CTA 高度、圆角和中心；
- 页面横向溢出；
- 图版关键标签是否位于 viewBox 内。

稳定后再增加截图回归，避免噪点滤镜和字体抗锯齿造成无意义失败。

### 14.1 建议技能

- `high-end-visual-design`：用于概念板和家族主构图的视觉评审，最终仍以本项目 Warm Ink 与家族语法为准。
- `browser:control-in-app-browser`：用于真实浏览器中的深浅主题、视口矩阵、控制台和交互验收。
- `diagnose`：用于资源加载、SSR / 水合、响应式或线上告警出现回归时的证据化定位。
- `imagegen`：只用于需要栅格气氛稿或材质探索的阶段；课程语义图版与可实施概念板优先使用确定性 SVG，不生成不可审计的位图结构。

## 15. 最后的判断标准

六类全部完成后，用户应感受到：

- 七个家族属于同一本算法图谱，但每一族拥有自己的形态和性格；
- 分类页不是目录包装，而是进入一种思维方式的入口；
- 课程页不是课件陈列，而是文字、图形和互动共同解释一个状态转移；
- 深浅主题、桌面与移动端只是同一内容的不同材质和排版，不是不同版本；
- 所有艺术细节都经得起“它在说明什么”的追问；
- 工程上新增或修复一个公共能力不需要复制修改七遍。

如果某个方案只能回答“更炫了”，却不能回答“更清楚地解释了什么”，就还没有达到 DP大师后续改造的标准。
